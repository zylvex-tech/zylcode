DEVELOPER PREVIEW · WAITLIST

The Engineering OS that shows its work.

ZylCode is being built to turn software-development instructions into verifiable engineering work. It combines repository intelligence, approval-gated execution, and an evidence ledger designed to make actions and results easier to inspect.

Built in public by Zylvex Technologies Limited, ZylCode maintains a capability registry that distinguishes implemented functionality, partial implementations, planned work, and claims awaiting independent acceptance.

The Developer Preview is planned as a free, invite-only release. Join the waitlist to receive an email when preview access becomes available — nothing else.

What works today

  • WORKING Agent workflow: prompt processing, repository-context retrieval, planning, approval-gated tool execution, and recording of execution evidence.
  • WORKING Repository intelligence: symbol and dependency navigation, typed query methods, and index-freshness reporting through the supported interfaces.
  • WORKING Factory and agent workflows: durable task graphs, human-approval gates, and persisted claims, with blocked gates remaining blocked.
  • WORKING Provider routing: configured provider routing and failover, with provider credentials supplied by users where supported.
  • LIMITED Installers: local installer builds are configured for supported platforms. Installers are not yet signed, and operating-system security warnings may appear.

What is not ready yet

  • NOT THERE Computer-use automation: currently simulated — the application does not actually control your screen.
  • PENDING Independent acceptance: some previously reported intelligence capabilities still require independent re-acceptance. The capability registry identifies claims awaiting that review.
  • NOT THERE Commercial availability: pricing and paid tiers have not been announced. The initial Developer Preview is intended to be free and invite-only.

Evidence and transparency

The public capability registry documents capability status and links to supporting evidence where available. Implementation, test coverage, and independent acceptance are distinct states; a passing test does not by itself establish independent acceptance.

The evidence ledger is hash-chained: a corrupted chain is an error, never a silent empty state. Registry: docs/capability-registry.json

ZylCode is pre-release software. Capability descriptions reflect the documented development state and are not guarantees of production readiness.
