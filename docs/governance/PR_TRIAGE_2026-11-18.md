# Open pull-request triage — 2026-11-18

Twenty-two PRs are open. They are not one backlog; they are four different
situations that a single "open PR count" flattens into a number nobody can act on.
This document records what each one is, what blocks it, and what would close it.

Read from `gh pr list --state open` and `gh pr view <n> --json files,body` on
2026-11-18. Nothing here merges or closes anything.

The reason these accumulate is not neglect: `strict=true` branch protection means
each one must be rebased after the previous lands, so a batch of sixteen is sixteen
serial rebases. The honest statement is that dependabot is configured at a cadence
the merge throughput does not support, and that is a settings change, not a review
task.

## 2. The MCP stack — a real dependency chain, not duplicates (4)

| PR  | What it is                                                                                                                | Blocked by                 |
| --- | ------------------------------------------------------------------------------------------------------------------------- | -------------------------- |
| #50 | real MCP client: transports, supervision, gated remote tools                                                              | its own review             |
| #51 | native tool calling across real providers                                                                                 | independent of #50         |
| #53 | desktop: native tool calling into the chat runtime                                                                        | #51 (consumes its surface) |
| #64 | **the real third-party server test** — spawns the published `@modelcontextprotocol/server-filesystem@2.3.0` through `npx` | #50 (stacked on it)        |

**#64 is the one worth harvesting.** Everything the client has been tested against
so far is this repository's own fixture (`tests/support/mcp_test_server.rs`), which
proves the client matches our reading of the protocol, not that it interoperates
with a server somebody else wrote. #64 adds three files and no dependencies:

- `crates/zylcode-mcp/tests/mcp_real_server.rs` — `initialize` version negotiation,
  `tools/list` schema retention, real `read_text_file`/`list_directory` round trips,
  a path outside the allowed root returning an error with no file content, session
  survival after that refusal, unknown-tool error, clean `shutdown`;
- `docs/architecture/MCP_CLIENT.md` — 26 lines on how to run it;
- `docs/governance/evidence/mcp_real_server_transcript_2026-11-11.txt` — a live
  transcript with a negative control (`…@9.9.9` fails both tests with npm `ETARGET`).

It is `#[ignore]`d (needs `npx` and network), which is exactly the quarantined class
the register in `docs/governance/FLAKY_TESTS.md` now covers — its entry would be
`external-dependency`, and the negative control is why it is worth having.

**Why it is not merged here:** it is stacked on #50, and merging #50 is a
transports-and-supervision change to the MCP client, not a test addition. Landing
#64 without #50 means rewriting its base; landing #50 without reading it is exactly
the kind of merge this repository's audit history warns about. The unblocking order
is #50 → #64, and the first step needs a reviewer with time to read the client.
