WHY THIS EXISTS
Phase 2A's accepted report recorded, truthfully, that symbol resolution was
regex-based and that IMPORT_RESOLVED / REFERENCE_RESOLVED were not implemented.
D1 requires them to be produced by a real resolver before those markers may be
retired. This file is the reproduction block for that change.

WHAT THE FIXTURES PROVE
  positive/        `use crate::account::Account;` in ledger.rs resolves to
                   account.rs AND to the Account symbol, DETERMINISTIC, line 1;
                   the type use inside ledger.rs resolves back to that symbol.
                   Coverage 100% for the fixture.
  unsupported/     A Python file is not inventoried by the scan, and naming it
                   with resolve_file returns UNSUPPORTED_SEMANTIC_INDEX with a
                   reason — not an empty result that reads as "imports nothing".
  parse_failed/    A syntax error is reported as PARSE_PARTIAL (tree-sitter
                   recovers), every edge from that file carries from_partial.
  invalid_utf8/    An undecodable file is excluded rather than treated as empty,
                   and naming it produces an explicit refusal.

KNOWN LIMITATION (declared, not hidden)
  117 of 331 indexed files parse with tree-sitter error nodes and are therefore
  reported as PARSE_PARTIAL. Their edges are real but labelled. This is a
  grammar-coverage question (tree-sitter-rust 0.24.2 against this codebase), not
  a fallback to regex: no edge is produced by text matching. The next packet
  should identify the construct(s) causing partial parses rather than widen the
  label. The repository-wide coverage figure (99.94%) is computed over imports
  we could see; the partial files are the ceiling on completeness, and are
  reported so the number cannot be mistaken for one.
